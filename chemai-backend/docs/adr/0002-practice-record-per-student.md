# 自适应练习记录：按学生组织独立 ExamRecord 而非设计文档 28 §9.3 的共享练习记录

设计文档 28 §9.3 将练习记录设计为按老师组织的共享记录（一份练习面向多位学生），但自适应练习是「一人一卷、逐人批改、错题归因」的个性化场景。本阶段选择按学生组织：练习、错题训练、每日练习各创建 per-student 的 `ExamRecord`（`exam_type=practice`/`homework`），每位学生一份独立题目与独立记录，题面从真题库复制（`source=practice`），与教师端 exam 六态流程完全隔离。

**Why 按学生独立记录**：
1. **权限边界**——`GET /api/practice/student/{uid}/tasks` 要求 student 仅可查自己的任务（跨学生 403），共享记录无法表达「这份练习属于谁」。
2. **错题归属**——错误作答要归因到具体学生（`StudentAnswer.student_id` + 复习任务 student-question 去重），共享记录下同一道题多人作答会互相污染统计。
3. **进度隔离**——自适应出题是逐人 ZPD 档位 + 薄弱知识点生成的个性化卷面，不存在「同一份卷面多人共用」的需求。
4. **不污染教师端**——共享记录会复用 `ExamRecord` 的教师六态生命周期（发布/批改/归档），学生练习不走该流程，硬塞进共享模型会破坏 exam-lifecycle 语义。

**调和方式**：记录表仍复用 `ExamRecord`（`class_id` 可空留白、`exam_type=practice/homework` 区分），不新增独立表；区别只在「粒度」——每条记录属于单个学生而非整个班级，`StudentAnswer` 逐题落库含 `answered_at` 时间戳（新增列）。教师端 exam 六态行为不变，练习记录不进入教师出题/审核/发布流程。

**后果**：练习/训练/每日练习会随学生规模增长产生更多 `ExamRecord` 行，属预期成本；「我的练习」「班级练习」等聚合查询需按 `student_id` 维度过滤而非 `class_id`。若未来出现真实的多班共卷场景，可再引入共享卷面模型并与 per-student 记录关联（未来迭代）。
