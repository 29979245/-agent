# 障碍诊断主轴：三维障碍类型而非知识板块迷思概念

课程详细版文档（48-障碍诊断引擎）将诊断输出设计为按知识板块组织的迷思概念（化学平衡/氧化还原…），但产品规格 doc 27 定义的主轴是三维障碍类型（concept/reading/expression）。本阶段选择以三维障碍类型为诊断主轴：规则引擎与 LLM 的输出在障碍类型轴上融合、冲突检测与落库都按障碍类型，知识板块与迷思概念名仅作为补救建议的附加信息。

**Why 三维障碍类型**：doc 27 是产品规格权威。三维障碍贯穿 `StudentAnswer.barrier_type` 落库、`Student.barrier_profile` 画像聚合、班级障碍分布、教师覆盖机制，并是下游消费方（doc 50 学情面板聚合 barrier_distribution、doc 57 Agent 的 diagnose_barrier、doc 49 自适应练习障碍策略矩阵）的全部语义基础。知识板块轴无法驱动这些产品行为，且文档 34 的枚举定义只有 `BarrierType`，没有"知识板块"枚举。

**调和方式**：详细版 48 的具体机制全部保留——22 条 YAML 规则（6 大知识板块）、0.6/0.4 加权融合公式、冲突消解决策表阈值（rule≥0.85 / llm≥0.9）、置信度标签（<0.6/0.6-0.8/≥0.8）——仅将融合与冲突检测的维度从"知识板块"替换为"障碍类型"。每条 YAML 规则额外携带 `barrier_type` 字段（化学平衡/氧化还原/摩尔/有机/物构→concept，化学用语→expression）。

**后果**：reading 障碍在 22 条规则中无覆盖（迷思概念库天然不含审题类错误），由 LLM 单独诊断，融合走"仅 LLM"行（`fused = 0.4×llm_conf`）；后续若需规则引擎覆盖审题错误，再补充 reading 类规则（未来迭代，doc 27 §十四）。
