# 家长认证 = 手机号 + 绑定码（绑定码即身份凭证），不做密码注册

设计文档 33 §二 原定义家长端为「手机号 + 密码登录 / 注册」。本阶段落地为：**家长首次以 `POST /api/parent/login`（body 手机号 + 绑定码）一步完成登录（无绑定则返回引导），绑定码既作身份凭证又作授权凭证；不实现密码注册，也无需独立绑定端点。**

**Why**：
1. **家长低频、弱信任**——家长月均登录 2-4 次，单独建密码/改密/找回流程成本高且无人维护；绑定码由学生端生成并口头分享，天然完成「学生授权家长」的身份信任闭环（设计 33 §决策二）。
2. **一次绑定即一次认证**——绑定码是一次性授权凭证，家长凭其既登录又绑定，减少一个端点与一套注册流程，符合「低频触点最少步骤」目标。
3. **与既有模型一致**——`Student.bind_code` 已是模型字段（doc 31/52 学生端「我的」页生成），无需为家长新增密码字段与迁移。

**调和方式**：`app/api/v1/auth.py::parent_login` 按 `phone + bind_code` 查询家长（不存在则创建），校验绑定码是否匹配某 active 绑定（或与 `Student.bind_code` 一致）；成功签发 `role=parent` 的 JWT，`parent_id` 取自 Account.role_id。绑定状态校验收敛到 `app/core/parent_auth.py::require_parent` 与 `require_bound_child` 守卫。

**后果**：家长无独立密码体系，若绑定码泄露仅影响单一学生且可经学生端重新生成旧码失效；未绑定家长的登录返回 403 引导绑定，前端登录页不出现注册入口。未来如需短信验证码登录，可复用同一 token 机制、仅替换凭证校验。
